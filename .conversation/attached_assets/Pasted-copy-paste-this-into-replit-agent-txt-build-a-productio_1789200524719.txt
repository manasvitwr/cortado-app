```txt
build a production-ready mvp web app called “tutord” – basically letterboxd for youtube tutorials/videos/playlists.

goal:
users can sign up, save youtube videos or youtube playlists, see thumbnails/titles/descriptions, write captions, summaries, notes, ratings, and organize them into personal lists/watchlists. the app should feel like a dark mobile-first letterboxd-style product for tutorials.

tech stack:
- next.js 14+ with app router
- typescript
- tailwind css
- shadcn/ui if available
- supabase for auth, postgres database, and row level security
- deployable to vercel
- all compute should be cloud-friendly, no local video processing, no scraping-heavy workflows
- use youtube oembed first for simple video metadata
- support youtube data api v3 if a YOUTUBE_API_KEY env var is present, especially for playlists
- use server routes/actions only for youtube api calls so keys are never exposed

core pages:
1. landing page
   - dark purple/black theme
   - app name/logo
   - short tagline: “track, review, and organize the tutorials you watch”
   - sign in / sign up buttons

2. auth
   - supabase email/password auth
   - google auth if simple to add
   - after login redirect to home

3. home/dashboard
   - greeting: “hello, {username}”
   - sections:
     - popular this month
     - popular lists this month
     - your watchlist
     - recently added
   - use real user data where possible
   - if empty, show polished sample placeholder cards

4. add page
   - input box where user can paste:
     - youtube video url
     - youtube shorts url
     - youtube playlist url
   - detect whether url is video or playlist
   - for video:
     - extract youtube video id
     - fetch metadata: title, thumbnail, author/channel, description if available
     - save to videos table
     - allow user to add:
       - caption
       - manual summary
       - notes
       - rating 1-5
       - watched / watchlist status
       - visibility public/private
   - for playlist:
     - extract playlist id
     - fetch playlist title, thumbnail, description if api key exists
     - fetch playlist items if api key exists
     - save playlist and videos
     - if no api key, save playlist url + title placeholder and tell user api key is needed for full import

5. video detail page
   - show large youtube thumbnail
   - title
   - channel
   - description
   - embedded youtube player
   - user caption
   - summary
   - notes
   - rating
   - watched status
   - edit/delete buttons for owner

6. playlists/lists page
   - users can create custom lists
   - list has:
     - title
     - description
     - cover thumbnail from first video
     - visibility public/private
   - users can add saved videos to lists
   - show stacked thumbnail cards similar to letterboxd lists

7. profile page
   - username/avatar
   - saved videos
   - public lists
   - watchlist
   - stats:
     - videos saved
     - videos watched
     - lists created

database schema:
create these supabase tables with rls enabled:

profiles:
- id uuid primary key references auth.users(id) on delete cascade
- username text unique
- display_name text
- avatar_url text
- created_at timestamptz default now()

videos:
- id uuid primary key default gen_random_uuid()
- youtube_id text unique not null
- title text not null
- thumbnail_url text
- channel_name text
- description text
- duration text
- original_url text
- created_at timestamptz default now()

entries:
- id uuid primary key default gen_random_uuid()
- user_id uuid references auth.users(id) on delete cascade
- video_id uuid references videos(id) on delete cascade
- caption text
- summary text
- notes text
- rating int check (rating >= 1 and rating <= 5)
- status text default 'watchlist' check (status in ('watchlist','watching','watched'))
- visibility text default 'private' check (visibility in ('private','public'))
- watched_at date
- created_at timestamptz default now()
- updated_at timestamptz default now()
- unique(user_id, video_id)

playlists:
- id uuid primary key default gen_random_uuid()
- youtube_playlist_id text
- owner_id uuid references auth.users(id) on delete cascade
- title text not null
- description text
- thumbnail_url text
- original_url text
- visibility text default 'private' check (visibility in ('private','public'))
- source text default 'custom' check (source in ('custom','youtube'))
- created_at timestamptz default now()

playlist_videos:
- id uuid primary key default gen_random_uuid()
- playlist_id uuid references playlists(id) on delete cascade
- video_id uuid references videos(id) on delete cascade
- position int default 0
- created_at timestamptz default now()
- unique(playlist_id, video_id)

rls policies:
- public can read videos
- users can read public entries/playlists
- users can read/write/update/delete their own entries
- users can read/write/update/delete their own playlists
- users can read/write/update/delete playlist_videos only for playlists they own
- users can read/update their own profile
- public can read public profiles

youtube handling:
- implement utility functions:
  - extractYouTubeVideoId(url)
  - extractYouTubePlaylistId(url)
  - isYouTubePlaylist(url)
  - getThumbnailUrl(videoId)
- support these formats:
  - youtube.com/watch?v=
  - youtu.be/
  - youtube.com/shorts/
  - youtube.com/playlist?list=
  - youtube.com/watch?v=...&list=...
- video thumbnails should use:
  - https://img.youtube.com/vi/{videoId}/maxresdefault.jpg
  - fallback to hqdefault if image fails
- for video title:
  - use youtube oembed endpoint:
    https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v={videoId}&format=json
  - if api key exists, use youtube data api for title, channel, description, duration
- for playlists:
  - if YOUTUBE_API_KEY exists, use youtube data api playlistItems endpoint
  - import first 25 videos in mvp
  - save playlist metadata and associated videos
  - if no api key, create playlist shell and show a friendly note

ui direction:
- mobile-first
- dark navy/purple background like the attached mockup
- soft rounded cards
- peach/pink text accents
- bottom tab nav on mobile:
  - home
  - explore
  - add
  - notifications placeholder
  - profile
- desktop should still work with centered max-width layout
- cards should show:
  - thumbnail
  - title
  - channel
  - rating/status
- list cards should show stacked thumbnails

important constraints:
- do not download or store youtube thumbnails
- store only youtube ids and thumbnail urls
- no video processing
- no transcript/summarization in v1 unless manually typed by user
- make the app actually runnable with environment variables:
  - NEXT_PUBLIC_SUPABASE_URL
  - NEXT_PUBLIC_SUPABASE_ANON_KEY
  - SUPABASE_SERVICE_ROLE_KEY only if absolutely needed server-side
  - YOUTUBE_API_KEY optional
- include clear setup instructions in README
- include sql migration file for supabase schema and rls policies
- make sure the app builds without the youtube api key, with graceful degradation

acceptance criteria:
- user can sign up/login
- user can paste a youtube video link and save it
- thumbnail and title appear
- user can add caption, summary, notes, rating, and status
- user can paste a youtube playlist link
- if api key exists, playlist imports videos
- user can create custom playlists/lists
- user can add saved videos to lists
- user can view dashboard, video detail, list detail, and profile
- app is deployable to vercel
- no local compute-heavy dependency
```

small note: if replit struggles, tell it to **ship video saving first, playlist import second**. playlist import is the only part that can get annoying because YouTube’s API key + quota stuff.
